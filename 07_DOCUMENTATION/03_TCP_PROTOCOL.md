# 03 - TCP Communication Protocol

## Overview

The Windows AI application and the Ubuntu ROS 2 environment run as independent software systems. To exchange information between them, the project uses a TCP client-server architecture.

Once the perception pipeline has processed a frame, the resulting detections are serialized into a JSON message and transmitted over a TCP connection. The ROS 2 bridge receives these messages, reconstructs the detection data and publishes it to the appropriate ROS 2 topics.

This communication layer provides a clear separation between AI processing and robotic integration while allowing both systems to evolve independently.

---

## Client-Server Architecture

The Windows application acts as the TCP client, initiating the connection and transmitting detection data whenever a new frame has been processed.

The Ubuntu ROS 2 bridge acts as the TCP server, continuously listening for incoming connections and processing each received message before forwarding the information into the ROS 2 ecosystem.

This architecture ensures that only one component is responsible for generating perception data, while the receiving system focuses exclusively on robotic communication.

---

## Message Format

Detection results are serialized using JSON before transmission.

Each message contains the information required to reconstruct the detected scene, including object classes, confidence scores, tracking identifiers, bounding box coordinates and additional metadata generated by the perception pipeline.

Using JSON provides a structured, human-readable format that is easy to debug and extend as the project evolves.

---

## Reliable Data Transmission

TCP was selected because it guarantees reliable and ordered delivery of transmitted data.

Unlike connectionless protocols, TCP ensures that messages arrive complete and in the same order in which they were sent. This reliability is particularly important for perception systems, where incomplete or corrupted detection data could lead to incorrect information being published inside the robotic environment.

Although TCP introduces a small communication overhead, the increased reliability makes it well suited for this prototype.
